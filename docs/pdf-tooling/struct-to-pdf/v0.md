# Struct to PDF, v0

Implementation plan for the first writer. v0 takes **one page** and writes **one PDF page**. It does not accept a multi-page document.

The page fields are the target page in [document-schema.md](../document-schema.md): trim size, bleeds, resources, and contents. The behavior of boxes, markup, and PDF page boxes is the one-page case of [json-to-pdf.md](../json-to-pdf.md). This file is the order to build it.

## Input and output

```bash
rust-reg render-page page.yaml -o out.pdf
```

`page.json` is the same object. Paths inside the page (`extracted_path`, and `source_path` on fonts) resolve relative to the page file.

The file is one page object, not a document:

```yaml
page_size:
  width: 595.28
  height: 841.89
  units: points
  bleeds:
    top: 8.5
    right: 8.5
    bottom: 8.5
    left: 8.5
resources:
  images: {}
  fonts: {}
contents: []
```

A file that contains `pages` or `metadata` is rejected. v0 does not pick `pages[0]` out of a document.

There is no `schema_version` on the page object. The page is valid when it has `page_size.bleeds`, and every text box and image placement has the target fields (`id`, `alignment`, `padding`, and either `text` or `image`). The current extractor tree is rejected.

Output is a PDF with exactly one page. On any error, no file is written.

## Definition of done

v0 is done when one test renders `tests/fixtures/struct-to-pdf/card.yaml` to a PDF on disk at `target/struct-to-pdf/card.pdf`, and that file is a single page a person can open.

The page trim is **90 mm × 130 mm**, with **3 mm** bleed on every side. The text box is **70 mm × 50 mm**, with its top-left at 10 mm, 30 mm, so it is centered on the 90 mm width. Text inside the box is aligned to the **center** horizontally and the **middle** vertically.

`page_size.units` is `mm`. The writer converts with `pt = mm * 72 / 25.4` before writing `MediaBox`, `BleedBox`, `TrimBox`, and `CropBox`.

```yaml
page_size:
  width: 90
  height: 130
  units: mm
  bleeds:
    top: 3
    right: 3
    bottom: 3
    left: 3
resources:
  images: {}
  fonts:
    font1:
      name: font1
      font_family: LiberationSerif
      weight: normal
      italic: false
      embedded: true
      source_path: fonts/LiberationSerif-Regular.ttf
    font2:
      name: font2
      font_family: LiberationSerif
      weight: bold
      italic: false
      embedded: true
      source_path: fonts/LiberationSerif-Bold.ttf
contents:
  - id: card-text
    posX: 10
    posY: 30
    width: 70
    height: 50
    alignment:
      horizontal: center
      vertical: middle
    padding:
      top: 0
      right: 0
      bottom: 0
      left: 0
    auto_scale: true
    text:
      font: font1
      font_size: 5
      leading: 0.5
      line_height: 6
      font_style:
        weight: normal
        italic: false
        underline: false
      preentered: '<span font="font1">{{name}}<br>{{surname}}</span><br><br><span font="font2"><bold>{{company name}}</bold></span>'
      content: null
```

The string is literal. Nothing replaces `{{name}}`, `{{surname}}`, or `{{company name}}`. The markup above is the shape. In the card file each of those three pieces is a long paragraph, so the block is taller than the box before scaling.

| Piece | Face | Breaks |
|---|---|---|
| `{{name}}` then `{{surname}}` | `font1` | one `<br>` between them |
| `{{company name}}` | `font2`, bold | two `<br>` before it, so one empty line |

The paragraphs are long enough that, at `font_size` 5 mm, the block is taller than the 50 mm box. `auto_scale` shrinks every font size, and `line_height` and `leading`, by one scale so the block fits. The three placeholders stay in the text.

The test fails if the PDF is missing, if the trim is not 90 mm × 130 mm, if any bleed side is not 3 mm, if the text operators do not contain those three placeholders, if the unscaled block already fits, if the drawn block is larger than the 70 mm × 50 mm box, or if the scaled block is not centered in that box.

## Out of scope

- More than one page, document metadata, and the PDF info dictionary
- HTTP
- Replaying `transformation_matrix` or content-stream operators
- JPEG 2000, `ICCBased`, and `DeviceCMYK`
- Font subsetting
- Justified alignment
- `ifSt`, a barcode entry (`ean13`, `code128`, `qr`), and a photo entry. The fields are [document-schema.md](../document-schema.md). They are drawn when the registration server integrates the page, in [printing-implementation-plan.md](../../registration-server/printing-implementation-plan.md) steps 8 through 10.

Images are not part of this definition of done. Steps 3 and 7 stay in the plan for the placement math, and they are not required to call v0 done.

## Code

New module `src/struct_to_pdf/`, called from `main` only for `render-page`. The extractor stays as it is.

| File | Responsibility |
|---|---|
| `mod.rs` | `render_page(page, base_dir) -> Vec<u8>` |
| `page.rs` | Serde types for the one page, validation |
| `geometry.rs` | Trim/bleed math and document point to PDF point |
| `images.rs` | Load a placement and emit an image XObject |
| `text.rs` | Markup parse, wrap, align, show text |
| `fonts.rs` | Embed a font file and map a run to it |

`lopdf` 0.38 builds the PDF. No new PDF crate.

## Coordinate conversion

Document space is the trim’s top-left, y down. PDF space is the media box’s bottom-left, y up.

```text
mediaWidth  = bleeds.left + page_size.width + bleeds.right
mediaHeight = bleeds.bottom + page_size.height + bleeds.top

MediaBox = BleedBox = CropBox = [0, 0, mediaWidth, mediaHeight]
TrimBox = [bleeds.left, bleeds.bottom,
           bleeds.left + page_size.width,
           bleeds.bottom + page_size.height]

pdfX = bleeds.left + documentX
pdfY = bleeds.bottom + (page_size.height - documentY)
```

For a rectangle, `documentY` in that formula is the rectangle’s bottom in document space (`posY + height`).

## Steps

Each step lands with the tests listed under it. A later step does not start by weakening an earlier test. The work and the test scenarios for each step are in [implementation-plan.md](implementation-plan.md).

### 1. Parse and validate

Load YAML or JSON into the page types. Reject:

- a document (`pages` or `metadata` present)
- missing `bleeds`, a negative bleed side, or a non-finite trim size
- a content entry that is neither text nor image
- missing `id`
- text box: alignment other than `left`/`center`/`right` and `top`/`middle`/`bottom`; padding side negative; padding wider or taller than the frame; missing `font`, `leading`, or `line_height`
- image placement: missing `resource_name`
- non-finite or negative `width` or `height` on a box

**Done when** a fixture page loads, and each rejection above returns an error that names the field or the box `id`. No PDF is created in this step.

### 2. Blank page and boxes

`render_page` on a page with empty `contents` returns PDF bytes. The single page has `MediaBox`, `BleedBox`, `TrimBox`, and `CropBox` as in the formulas above. `UserUnit` is not written (the input widths are already in points).

**Done when** a test loads the bytes with `lopdf` and reads those four rectangles for a page with 9 pt bleeds on every side, and for a page with all bleeds `0` (trim equals media).

### 3. JPEG images

For a placement whose resource `file_format` is `jpg`, embed the file as a `DCTDecode` image XObject and paint it with `Do` into the placement rectangle, using the coordinate conversion. Paint `contents` in array order. Clip to the media box so a placement that hangs into the bleed is still drawn.

Ignore `transformation_matrix`. A missing file, a resource name that is not on the page, or a format other than `jpg` is an error naming the placement `id`. BMP and JPEG 2000 are step 8 of the implementation plan; until then they fail with a clear “not in v0 yet” error rather than a wrong image.

**Done when** a page with one JPEG placement round-trips the rectangle: the content stream’s transform maps to `posX`, `posY`, `width`, `height` in trim space, including a placement with a negative `posX` (inside the left bleed).

### 4. Plain text, one font

Font resources carry `source_path`, the file written by the extractor ([extractor/plan.md](../extractor/plan.md)). Until that step exists, the page author supplies the same field:

```yaml
fonts:
  F1:
    name: F1
    font_family: LiberationSerif
    weight: normal          # normal | bold
    italic: false
    source_path: fonts/LiberationSerif-Regular.ttf
```

Embed that TTF as a simple font (or a Type0 / Identity-H font if that is what `lopdf` embeds cleanly). Generate `ToUnicode` from the characters actually drawn so the PDF’s text is Unicode. Use the font’s advance widths for line width. Do not use the extractor’s hardcoded CID map.

Draw a text box whose string has no tags:

- use `content` when it is a string, including `""`
- otherwise use `preentered`
- error if both are absent, naming the box `id`
- error if no font resource matches the box `font` key or a span’s `font` attribute

This step only places a single line: `horizontal: left`, `vertical: top`, padding `0`, no wrapping. The baseline is `contentY + ascent`.

**Done when** a PDF with the string `Сергей` extracts back to that string, and the text matrix origin matches the box’s top-left plus ascent.

### 5. Wrap, alignment, padding

Inset by `padding` to the content box from the schema. Wrap on spaces to `contentWidth`. `<br>` is a forced break. A word longer than `contentWidth` stays one line and may extend past the content box; the frame clips. The distance from one baseline to the next is `line_height + leading` of the run that ends the line. Both values come from the box unless a span or `<leading>` overrides them.

| `alignment.horizontal` | Line x |
|---|---|
| `left` | `contentX` |
| `center` | `contentX + (contentWidth - lineWidth) / 2` |
| `right` | `contentX + contentWidth - lineWidth` |

| `alignment.vertical` | Block |
|---|---|
| `top` | First line at `contentY` |
| `middle` | Block top at `contentY + (contentHeight - blockHeight) / 2` |
| `bottom` | Last line ends at `contentY + contentHeight` |

Underline is a stroke under the run when `font_style.underline` is true. Padding stays empty.

**Done when** the card box in the definition of done places the text block in the middle of the 70 mm × 50 mm frame, each line is centered in that frame, and a separate right/bottom fixture still sits on the content box’s right and bottom edges.

### 6. Markup

Parse `content` or `preentered` with the subset in [document-schema.md](../document-schema.md): text (with `&lt;` `&gt;` `&amp;`), `<br>`, `<b>`, `<bold>`, `<i>`, `<u>`, `<span font="…" leading="…" line-height="…">`, and `<leading>N</leading>`. A span’s `font` attribute names the face for the text inside that span. `</span>` only closes it. Tags may nest. Any other tag is an error naming the box `id`.

A span overrides font, and leading or line-height when those attributes are present. `<leading>` overrides leading only. `<bold>` sets weight to bold and keeps the current font. The face is the font resource key (`font1`, `font2`), which must have a `source_path`.

**Done when** the card PDF contains `{{name}}` and `{{surname}}` in the `font1` file and `{{company name}}` in the `font2` file, with a blank line between the surname and the company name. An unknown tag writes no PDF.

### 7. BMP images

Accept `file_format: bmp`. Decode the BMP to RGB or gray samples and embed an image XObject (`DeviceRGB` or `DeviceGray`, no `DCTDecode`). Placement math is the same as step 3.

**Done when** a BMP placement occupies the same rectangle as the equivalent JPEG test.

## CLI

The test calls `render_page` and writes `target/struct-to-pdf/card.pdf`. Add the `render-page` subcommand in the same change so the same YAML can be rendered by hand:

```bash
rust-reg render-page tests/fixtures/struct-to-pdf/card.yaml -o target/struct-to-pdf/card.pdf
```

The CLI only parses paths and writes the bytes.
